# dsh-agnes-image

**Image generation plugin for DeepSeek Harness** — text-to-image, image-to-image, and
multi-image composition powered by **Agnes AI** (`agnes-image-2.5-flash`).
Zero dependencies, plain JavaScript, no build step.

[中文说明在这里](README.md) · Keywords: `dsh` `dsh-plugin` `deepseek-harness` `agnes` `agnes-ai`
`image-generation` `text-to-image` `image-to-image` `image-editing` `ai-image`

![A pelican painting at an easel — generated by this plugin with agnes-image-2.5-flash (1K / 16:9)](docs/preview.jpg)

> Unofficial community plugin, not affiliated with DeepSeek or Agnes AI. MIT, no warranty.

## What it does

It adds one tool, `agnes_generate_image`, to Harness. Ask for a picture — or ask to restyle
one you already have — and the model calls it. Then:

1. the result is **downloaded and saved immediately** into your session workspace (no expiring link),
2. it is **shown inline in the conversation** (not just a path),
3. it lands under a **date-stamped folder** so a few hundred images never become one junk drawer.

```
D:\your-project\generated-images\2026-10-10\a-cheerful-pelican-on-a-bicycle-120933.png
```

**Scope** — one tool: text-to-image, image-to-image, multi-image composition.
No gallery, no canvas, no batch queue. Video is out of scope.

## Install

Prerequisites:

1. **DeepSeek Harness** — desktop app, or `npx @deepseek-ai/dsh web` on Node `^22.19.0 || >= 24`.
2. **An Agnes API key** — see [API key](#api-key). Image models are currently free.

```sh
# From npm (once published)
dsh plugin --profile web add dsh-agnes-image

# From GitHub source
dsh plugin --profile web add github:Naskete/dsh-agnes-image

# From a local checkout (handy while developing)
dsh plugin --profile web add D:\path\to\dsh-agnes-image

# From a tarball
dsh plugin --profile web add D:\path\to\dsh-agnes-image-0.1.0.tgz
```

`<profile>` is usually `web` or `desktop`. Check with `dsh plugin --profile web list`,
uninstall with `dsh plugin --profile web remove dsh-agnes-image`.

**Restart Harness afterwards** (on the desktop app, quit from the tray icon — clicking the
window's X only minimizes it).

> **Why no `allowBuilds` prompt when installing from GitHub?**
> pnpm ≥10 refuses to run a git dependency's build scripts until the user allowlists them.
> This package is plain JavaScript, dependency-free, with **no install-time scripts**, so
> there is nothing to allow. That conclusion holds for this project only — any other plugin
> that asks for the allowance is asking to execute its own code on your machine at install
> time. Only allow sources you trust, and pin a commit (`github:you/repo#<sha>`).

### Graphical install

Harness → **Plugins** → **+ Add plugin** → type `dsh-agnes-image` (npm package name) or an
absolute local path → **Install** → fully quit and reopen Harness. The GUI pre-checks the
registry, so a `github:` address has to go through the CLI instead.

**How you know it worked:** the tool `agnes_generate_image` shows up, and asking for a picture
produces one instead of "I can't generate images".

## API key

Create one at [agnes-ai.com](https://agnes-ai.com) → console → **API Key management** → create
and copy the value beginning with `sk-`. (Copy the **value**, not the **name** you gave the key.)

Resolution order, first hit wins:

| # | Where | Notes |
|---|---|---|
| 1 | Loader row `config.apiKey` | most direct |
| 2 | Environment variable `AGNES_API_KEY` | read once at process start — restart Harness after `setx` |
| 3 | Key file `~/.dsh/agnes-image.config.json` | **recommended**: `{ "apiKey": "sk-..." }`, re-read on every call, no restart needed |
| 4 | File named by `AGNES_API_KEY_FILE` | secrets kept elsewhere |

```sh
# Windows (permanent, then restart Harness)
setx AGNES_API_KEY "sk-your-key"

# macOS / Linux
export AGNES_API_KEY="sk-your-key"     # add to ~/.bashrc or ~/.zshrc to persist
```

The plugin never writes your key anywhere, and the key file is excluded from version control
by convention — keep it out of repositories and screenshots.

## Usage

Just talk to the model:

> Generate: a cheerful pelican riding a red bicycle along a sunlit seaside boardwalk, cinematic realism, 16:9

Tool parameters (the model fills them in; you can also dictate them):

| Parameter | Type | Description | Default |
|---|---|---|---|
| `prompt` | string | **required.** What to draw, or how to edit. Detailed prose beats keyword soup | — |
| `model` | enum | `agnes-image-2.5-flash` / `agnes-image-2.1-flash` / `agnes-image-2.0-flash` | `agnes-image-2.5-flash` |
| `size` | string | Tier `1K`/`2K`/`3K`/`4K`, or an explicit `1024x768`-style `WxH` | `1K` |
| `ratio` | enum | Aspect ratio paired with a tier: `1:1` `3:4` `4:3` `16:9` `9:16` `2:3` `3:2` `21:9` | `1:1` |
| `image` | string[] | References: public HTTPS URL, Data URI, or a **local file path** (inlined automatically) | none |
| `outputName` | string | Base filename without extension; unsafe characters and Windows device names are rewritten | prompt slug + timestamp |

Modes:

| Mode | Ask like this | How the plugin calls the API |
|---|---|---|
| Text-to-image | "generate …", "I need a wallpaper of …" | `prompt` (+ optional `size`/`ratio`) |
| Image-to-image | "turn this into a rainy cyberpunk night, keep the composition" + a path or URL | `image` with one reference |
| Multi-image composition | "combine these: the first is the character, the second the product" | `image` with several references, in order |

Local references are read from disk and inlined as base64 (12 MB per image, by design: the API
fetches images over the network and cannot see your filesystem).

### Output dimensions

| Ratio | 1K | 2K | 3K | 4K |
|---|---|---|---|---|
| `1:1` | 1024x1024 | 2048x2048 | 3072x3072 | 4096x4096 |
| `3:4` | 864x1152 | 1728x2304 | 2592x3456 | 3456x4608 |
| `4:3` | 1152x864 | 2304x1728 | 3456x2592 | 4608x3456 |
| `16:9` | 1312x736 | 2624x1472 | 3936x2208 | 5248x2944 |
| `9:16` | 736x1312 | 1472x2624 | 2208x3936 | 2944x5248 |
| `2:3` | 832x1248 | 1664x2496 | 2496x3744 | 3328x4992 |
| `3:2` | 1248x832 | 2496x1664 | 3744x2496 | 4992x3328 |
| `21:9` | 1568x672 | 3136x1344 | 4704x2016 | 6272x2688 |

For `1920x1080` / `2560x1440` display assets, request `2K` + `16:9` and crop downstream:
those exact sizes are not native outputs and get normalized by the service.

### Prompt shapes (from Agnes's own guidance)

- **Text-to-image**: `[subject] + [scene] + [style] + [lighting] + [composition] + [quality]`
- **Image-to-image**: `[change] + [new style or scene] + [add/remove] + [must preserve]`
- **Composition**: state each reference's role, how they relate, and the target style.

## Configuration

Override the row in your profile's `cordis.patch.yml` (`$DSH_HOME/profiles/<name>/cordis.patch.yml`):

```yaml
- id: agnes-image
  name: dsh-agnes-image
  config:
    apiKey: ''                                     # empty falls through to the lookup order
    baseUrl: https://apihub.agnes-ai.com/v1        # mainland mirror: apihub.agnes-ai.cn
    model: agnes-image-2.5-flash
    outputDir: generated-images                    # relative to the session workspace
    timeoutMs: 300000                              # Agnes recommends 60s-360s
```

A patch **replaces the whole `config`**, it does not deep-merge: restate every key you want to keep.

Unknown fields are rejected rather than silently ignored, so a typo in a key name surfaces
immediately.

## Troubleshooting

Start here: (1) fully quit and reopen Harness; (2) confirm the key is reachable;
(3) confirm the network: `curl https://apihub.agnes-ai.com/v1/models -H "Authorization: Bearer sk-..."`.

| Symptom | Cause | Fix |
|---|---|---|
| No `agnes_generate_image` tool | plugin not installed / not restarted | reinstall, then fully quit Harness |
| `Agnes API key is missing` | none of the four sources has a key | write `~/.dsh/agnes-image.config.json` |
| `401` / `403` | wrong key value (often the key's *name*) | copy the `sk-` value again |
| `404` | unknown model id | use `agnes-image-2.5-flash` / `2.1-flash` / `2.0-flash` |
| `429` | rate limited | wait, or slow the request rate |
| `Invalid size` / `Invalid ratio` | unsupported values | use a tier or `WxH`; pick a ratio from the table |
| `Cannot read the reference image` | wrong local path | use an absolute path, or a public URL |
| `... the limit is 12 MB` | reference image too large | compress it, or host it and pass a URL |
| `non-JSON body` | a gateway/proxy returned HTML | check network, proxy, `baseUrl` |
| Generation takes 30s+ | normal | nearly all of it is the provider generating |

## Security and privacy

**Your key** goes into one HTTP header (`Authorization: Bearer …`) sent to the `baseUrl` you
configured, and nowhere else: it is never logged, never echoed into the conversation, and the
error messages only ever contain the *path* where a key is expected.

**Your prompt, references and results** travel through Agnes's servers — that is how a cloud
image model works. The plugin never uploads anything from your workspace on its own; a local
file is only read when a path is explicitly named in the tool's `image` argument.

Because that argument can be steered by a model (or by a prompt injection), three gates guard
what may leave the machine, and three more guard what may land on disk:

| Direction | Gate |
|---|---|
| local file → Agnes | bytes must sniff as PNG / JPEG / WebP / GIF, otherwise refused (so `~/.ssh/id_rsa` cannot be smuggled out as a "reference image") |
| local file → Agnes | 12 MB per file (they are inlined as base64) |
| caller → Agnes | `data:` URIs must be `data:image/…;base64,…` |
| provider → disk | download URL must be `http(s)` |
| provider → disk | 64 MB cap, checked against `content-length` and the real body |
| provider → disk | content must be an image (magic bytes or `image/*`), otherwise nothing is written |

**Session logs:** DSH stores the conversation verbatim under `~/.dsh/sessions/`, including any
key you paste into the chat. Do not commit that directory — the plugin's install adds ignore
rules to `~/.dsh/.gitignore`. If a key was ever exposed, revoke it in the Agnes console and
create a new one.

**What the plugin can do on your machine:** two things only — make HTTP requests, and write
image files into the workspace. It runs no shell commands, evaluates no code, ships no
dependencies, and reads no file you did not name.

## FAQ

**Does it cost anything?** The plugin is free and open source; Agnes's image models are
currently free (check their pricing page).

**Do I have to say "draw"?** No. Any phrasing works as long as the intent is to create or edit
an image.

**Offline?** No — generation happens in the cloud.

**Several images per call?** One call returns one image. Ask for "three variations" and the
model will call the tool several times.

**Where do the files go?** `<session workspace>/generated-images/<date>/`, unless you change
`outputDir`.

**Can I edit an existing photo?** Yes — give the model the path or URL and describe the change.

## Design notes

- **Zero dependencies.** Node built-ins only; no `@deepseek-ai/*` imports. Published DSH keeps
  zod behind a hashed pnpm path that is not resolvable from an installed bundle, so the
  Standard Schema contract is implemented by hand.
- **`response_format` goes in `extra_body`.** Agnes rejects it at the top level, and reference
  images must ride in `extra_body.image`; a test asserts both.
- **Download immediately.** Provider URLs are signed and not guaranteed to live; bytes are
  written into the workspace, and registered as a session attachment so the image renders inline.
- **Session workspace, not the process directory.** The host's cwd is the launcher's directory;
  the plugin resolves the calling session's workspace through `workspaceRegistry`.
- **`ratio` only with a tier size.** An explicit `WxH` already fixes the shape.
- **12 MB inlining cap** for local references, with an error that explains why.
- **Windows reserved device names** (`CON`, `NUL`, `LPT1`, …) are rewritten to `CON-image.png`.
- **Key re-read per call**, so rotating a key never requires a restart.

```sh
node --test            # fully offline: fake fetch, no API key, no network
node --check index.js
```

Live debugging without restarting Harness: append to your profile's `cordis.patch.yml`

```yaml
- insert:
    - id: agnes-image
      name: dsh-agnes-image
      config:
        model: agnes-image-2.5-flash
```

`dsh plugin add` for the same package — two rows would register the same tool twice.
